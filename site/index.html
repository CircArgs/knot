knot compiles a typed Python spec into postgres SQL — DDL, reads, ER writes, validation. Pure library, zero connections, zero scheduler. hitch is the reference Temporal + FastAPI + pgvector deployment that proves the substrate is real.

The problem

Three data providers each have an opinion about the same movie. They disagree on runtime, on title case, on whether Paul Thomas Anderson should also be P. T. Anderson. A typical MDM stack solves this with a heavyweight commercial product that bundles the spec, the deploy engine, the write pipeline, the matching policy, and the runtime into one opinionated box.

knot ships only the compiler layer. You keep your migration tool, your workflow engine, your ER policy, your API style, your auth. The substrate replaces the one thing that's actually a compiler problem.

The five-bullet north-star

Every change to knot has to justify against these. They're locked.

01
Compile a typed spec to postgres SQL
Spec.ddl() emits the target schema. Query.sql() emits read SQL. binding.write_sql / assign_canonical_sql / retract_sql / translate_fks_sql emit write SQL. The host runs the strings.
02
Fuse multi-source claims into one view
N sources publish bindings about the same entity. The _resolved view picks per-slot winners via argmax over per-(source, class, slot) weights. _all_sources exposes per-source jsonb provenance.
03
ER as a first-class write primitive
assign_canonicals_sql is one atomic CTE chain: stamp + forward FK translation + backward fan-out + register. recanonicalize cascades graph-wide. No ORM expresses this.
04
One typed AST for reads + virtuals + constraints
cls.col.year >= 1888 is the same Expr in .where(...), add_constraint(...), and add_virtual(...). Three retrieval shapes (relational / graph-walk / k-NN), one builder.
05
knot is a substrate, not a runtime
No connections, no scheduler, no migration engine, no ingest worker, no ER policy decisions. The host owns all of that; knot just compiles. → that split is what makes the substrate trustable.

The spec is the single source of truth

Authored once in typed Python. The same Expr nodes compose in .where() filters, constraint bodies, and virtual-class predicates. There's no DDL file to drift from the spec. 

from knot import Spec, types, this

spec = Spec(identifier_slot_name="canonical_id", schema="hitch")

person = spec.add_class("Person")
person.slot("name", types.TEXT, required=True)
person.slot("birth_year", types.INTEGER)
person.slot("name_embedding", types.VECTOR(384, metric="cosine"))

movie = spec.add_class("Movie")
movie.slot("title", types.TEXT, required=True)
movie.slot("year", types.INTEGER)
movie.slot("director", person)              # FK
movie.slot("title_embedding", types.VECTOR(384, metric="cosine"))
movie.slot("mpaa_rating", types.ENUM("G", "PG", "PG_13", "R", "NC_17", "NOT_RATED"))

# NULL-safe FK chain in a constraint body
movie.add_constraint(
    "director_alive_at_release",
    body=movie.col.director.birth_year.is_null()
       | movie.col.year.is_null()
       | (movie.col.director.birth_year < movie.col.year),
)

# Correlated aggregate — Movie has at least one director credit
credit = spec.add_class("Credit")
credit.slot("role", types.ENUM("director", "actor", "writer", "producer"), required=True)
credit.slot("movie", movie); credit.slot("person", person)

movie.add_constraint(
    "movie_has_director_credit",
    body=movie.col.director.is_null()
       | ((credit.col.movie == this.Movie) & (credit.col.role == "director")).any(),
)

# Virtual subclass — predicate composes from any Expr
movie.add_virtual("DirectedMovie", where=movie.col.year >= 1888)

# Three sources, one binding per source per class
for src in ("imdb", "tmdb", "rottentomatoes"):
    s = spec.add_source(src)
    for cls in (person, movie, credit):
        s.bind(cls)

print(spec.ddl())                # one canonical CREATE script
print(spec.emit_validation())    # one SELECT per constraint

Entity resolution in one atomic statement

Every binding.assign_canonicals_sql() call does four things at once in a single writable-CTE chain. Re-runs on already-stamped rows are strict no-ops.

1
Stamp
UPDATE bindings SET canonical_id = … WHERE canonical_id IS NULL
No-op if already stamped — idempotency guard
2
Forward FK translation
Look up each ClassRef slot's value in target.bindings (same source). Rewrite source-id → canonical-id.
3
Backward fan-out
For each referencing class, UPDATE its FK column where it held this row's source-id. EXISTS-guard ensures strict idempotency.
4
Register
Implicit — no separate canonical table. The set of known canonicals is SELECT DISTINCT canonical_id FROM bindings.
Embedding-driven ER in hitch (real, not mocked):
-- For each unresolved binding in source X:
SELECT
  u.source_identifier,
  (SELECT b.canonical_id
   FROM <class>_bindings b
   WHERE b.canonical_id IS NOT NULL
     AND b.source_name <> X
     AND b.name_embedding <=> u.name_embedding < 0.35
   ORDER BY b.name_embedding <=> u.name_embedding
   LIMIT 1) AS match_canonical_id
FROM <class>_bindings u
WHERE u.source_name = X AND u.canonical_id IS NULL;

hitch — the reference deployment

What a real team would build around knot. Read it as "here's the substrate in action", not part of knot. The split is deliberate — your team can replace any of these pieces without touching knot.

every DB write
goes through a knot SQL emitter. Never raw SQL.
workflow code
never imports knot. Only activities do. Replay-safe by construction.
re-ingest safe

model drift auditable

Try it

One docker compose up brings up the whole stack — postgres, Temporal, the API, the worker, the GraphQL playground. 

cd hitch
docker compose up --build              # postgres + temporal + api + worker
docker compose exec hitch-worker python -m scripts.deploy    # DDL + seed weights
docker compose exec hitch-worker python -m scripts.run_demo  # ingest → embed → ER → validate

  -H 'content-type: application/json' \

  -d '{"query":"mutation { retract(class_name: \"Movie\", canonical_id: \"m_…\", source_identifier: \"my-fix\") }"}'

Where it doesn't oversell

Five hard-nosed personas reviewed the pitch. All approved with gaps. These are the gaps. Substrate-side ones are closed in the current commit; host-side ones are explicitly out of scope for knot itself.

closed P0 — corrections weight silent-failure
Operator forgets to seed _user_corrections at high weight → every GraphQL mutation appears to succeed but later reads return the pre-correction value. Fix landed: new emit_weight_seed in knot always inserts the corrections row at CORRECTIONS_DEFAULT_WEIGHT (1e6) regardless of caller-supplied defaults. INSERT-only so operator tuning survives re-deploy.
closed ER fan-out lock-ordering hazard
Two ER workers stamping different sources whose fan-outs share referencing classes could acquire row locks in different orders → deadlock setup. Fix landed: cls.referrers iteration now sorts by class name in emit_assign_canonical(s)_sql — deterministic across spec construction orders.
closed explain_winner_sql tie-break divergence
Used RANK() OVER (ORDER BY weight DESC) while the resolver tie-broke on weight DESC, source_name. Diagnostic labeled tied-weight rows both is_winner=true while the view picked one. Fix landed: ROW_NUMBER() with the same ordering tuple as the resolver. Margin now NULL for single-source slots instead of misleading 0.0.
closed Embedding model drift unauditable
A future model upgrade produces different cosine distances → prior ER decisions stay stamped but new ones fuse differently. Fix landed: hitch's er_metadata now records model_name + embedding_dim on every stamped row. A backfill script can scan for stale models and re-decide.
open GraphQL N+1 → proper DataLoader
Per-request memoization halves roundtrips on the demo (Tarantino in N credits = 1 lookup, not N). True batched IN-list DataLoader for distinct targets per-request is the next step. Lives in knot_graphql.Resolvers.
open DLQ shape + cursor durability in hitch
Ingest workflow currently discards validation-fail rows after counting them. Production needs a routed sink. fetch_seed_batch reads from disk — production needs cursor durability and rate-limited source-API calls. Both are host concerns; knot's substrate doesn't change.
open ER needs_review bucket
Today's policy is binary: below threshold → match, above → mint fresh. A 0.30–0.45 distance band should route to human review instead of producing an irrecoverable fresh canonical. Host-side policy add.
open Resolved view scaling
Per-slot correlated subqueries are charming at demo scale and ~25× more buffer hits than a window-function rewrite at 10M bindings. Plan to ship an opt-in emit_resolved_view_window for production cardinality.
